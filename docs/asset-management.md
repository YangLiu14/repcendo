# 动画资产版本管理

按用户要求，运动动作的模型、图片、纹理、视频和验收画面仅保存在本地，不进入 Git 或 Git LFS。Git 保存代码、文字规格、资产路径及摘要、审核报告和使用说明；App 图标及不含动作画面的界面截图继续跟踪。

## 最近完成的工作

截至 2026-10-30，当前工作区已交付 48 个动作、96 段男女版本视频及封面，App 动画目录共 193 个文件。最近的工作分为四部分：

1. **人物形变与握持修复**：调整骨架蒙皮、前臂扭转分配和手指控制，修复卷腹握持方向与死虫式肩腋拉伸；增加完整循环的回归检查及多视角证据。
2. **动作库扩展**：在原 20 个动作基础上，通过四批制作新增 28 个动作。动作规格、场景、审核结果及成品来源分别记录，按精确动作 ID 接入 App。
3. **器械照片复核**：先查看厂家实物照片，再比对承力结构、转轴、握把和运动路径。当前 48 个动作均已登记照片对照结果；最近修订 17 个动作的 34 个版本，通过 4,402 帧检查，输出 4,368 帧成品，保留其他 124 个视频及封面的原始字节。
4. **发布与交付**：将碰撞、形变、握持、器械运动和人工图片审核绑定到场景及检查器摘要；完整解码成片后同步网页和 App。最近一次 iOS 模拟器构建成功，193 个构建资源与源码摘要一致。

完整动作验收与器械照片复核是不同记录。[覆盖清单](animation-library/inventory.json) 中 47 个动作通过现行检查，旧深蹲 1 个仍待新流程复核；1,276 个目录动作尚未制作动画。最新批次尚未安装到手机。第 005 批正在另一个任务中制作，尚未交付；本次提交可能包含其进行中的代码快照，不将它计入已交付范围。上述动画与构建结果为此前交付记录，本次资产管理变更不重新渲染。

实现入口见 [制作流水线](animation-pipeline.md)，详细进度见 [工作记录](../progress.md)，器械结论见 [复核结果](equipment-references/current-assets-review.md)。

## 文件如何保存

| 用途 | 当前路径或例子 | 管理方式 |
| --- | --- | --- |
| App 动作视频与封面 | `Repcendo/Resources/ExerciseAnimations/` | 本地保留、Git 忽略；只提交 `catalog.json` |
| 人物设计、纹理、模型、骨架 | `docs/character-concepts/`、`docs/character-assets/` 中的媒体与模型 | 本地保留、Git 忽略，不启用 LFS |
| 动作场景及网页媒体 | `docs/animation-*/` 的 `.blend`、MP4、PNG、GIF 等 | 本地保留、Git 忽略 |
| 人体与器械验收画面 | `*-review.jpg`、审核图目录、形变研究配图 | 本地保留、Git 忽略；JSON 审核报告及哈希进入 Git |
| 动作播放截图 | `docs/screenshots/animation-*` | 本地保留、Git 忽略 |
| 代码、规格、目录与报告 | Python、HTML、JS、CSS、MD、JSON、CSV、TXT | 提交 Git；不在这些文件中内嵌图片或模型数据 |
| App 图标及一般界面截图 | `Repcendo/Assets.xcassets/`、其他 `docs/screenshots/` | 继续提交 Git |
| 原始帧、候选、日志及自动备份 | `build/`、`motion-frames/`、`*.blend1` 等 | 忽略，和正式本地资产分开保存 |

`.gitignore` 对人物及动画目录采用文字类型白名单，因此新增未知模型或媒体格式默认也会被忽略。不要用 `git add -f` 绕过规则。已有资产通过 `git rm --cached` 只移出索引，原文件留在原路径；当前机器的网页预览、App 打包和动画验收继续读取这些文件。

审核图片和正式场景仍参与发布验证，缺少本地文件时应恢复资产，不能跳过哈希或人工审核要求。`catalog.json` 只是路径与摘要，不包含视频和封面本身。

本次解除跟踪 226 个旧资产及生成记录，约 478.4 MiB，已核对本地原件和归档摘要完全一致。暂存快照中没有新增或修改的二进制文件；192 个本地 App 视频及封面与 48 项目录中的摘要一致。37 项流水线门禁/交付测试与 14 项核心测试通过，92 个 Python 文件和 459 个 JSON 文件语法检查通过。

## 换电脑与恢复

单独克隆代码仓库不包含人物模型、动作视频、纹理和审核图片。需要从自己的本地或私有备份恢复同样的相对路径，再运行动画检查、同步脚本或打包 App。缺少媒体的 checkout 不能用于验收离线动画功能。

本次解除跟踪前，将原来已被 Git 跟踪的私有资产保存为 `build/local-assets/untracked-assets-2026-10-30.tar`，对应清单为同目录的 `untracked-assets-2026-10-30.json`。这份归档只保护本次解除跟踪的旧文件，**不是所有新资产的完整备份**。归档仍在同一磁盘，不是异地备份。

完整私有备份需要保留 `Repcendo/Resources/ExerciseAnimations/`、`docs/animation-*/`、`docs/character-assets/`、`docs/character-concepts/`、`docs/equipment-references/`、`docs/research/deformation-evidence/` 和动作播放截图。把这些文件连同对应代码版本存入自己的备份位置，保留相对路径。备份包括审核报告，恢复后按报告中的 SHA-256 检查一致性；对正在制作的批次，先等待文件停止写入再备份。

## Git 历史的边界

本次只创建本地提交，不 push，也不上传到 LFS 或其他服务。[Git 官方文档](https://git-scm.com/docs/gitignore) 说明忽略规则不会自动处理已跟踪文件；停止跟踪也不会删除过去提交中的内容。旧资产仍存在于本地或已有远端的旧提交中。

如果今后要保证整个远端历史不包含动作资产，需要先备份并单独清理历史，再验证将要推送的所有提交。本次不改写历史，因此不能把本次移除理解为历史资产已清除。
